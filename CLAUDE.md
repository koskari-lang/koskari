## Commands

**All Python execution goes through tox. Never invoke `python`, `python3`, `pip`, or `pytest` directly.**

For a short probe of a Python API or of Koskari syntax, use `uv run python3` or `uv run koskari`. Do not reach for `tox -qe py -- -c` to do it. Never pass `-r` or `--recreate` to tox; if an environment is broken, diagnose the cause.

```bash
# Run full test suite (phases in order)
make test

# Run a specific test file or directory
tox -qe py -- tests/lib/test_pair.py
tox -qe py -- tests/compile/specials/

# Run tests with native debugger output
tox -qe gdb -- tests/<path>

# Short behavior probe (not tox)
uv run python3
uv run koskari

# Lint (flake8)
make lint

# Build docs (Sphinx)
make docs

# Static analysis on koskari/lib (no compile step)
make cppcheck        # cppcheck via pre-built container; writes build/cppcheck.sarif
make flawfinder      # Flawfinder via tox
```

## Architecture

Koskari is a LISP dialect for Python. It has three major layers that must be built in order: the C extension, then the Python compiler, then the bootstrap `.ki` sources that are compiled at load time.

### C Extension (`koskari/lib/`)

The native extension is the runtime foundation. It provides:

- **Types**: `atom.c/h` (symbol, keyword — interned), `pair.c/h` (cons cells + nil), `values.c/h` (multi-value return), `defer.c/h` (coroutine deferral), `namespace.c/h` (lexical scopes), `ref.c/h` (reference cells), `formals.c/h` (function parameter handling).
- **Bytecode**: Opcodes are defined in `opcodes.incl` using the `OP(name, cache_slots, style)` macro, or its seven-argument form `OP(name, cache_slots, EXTRA, f0, f1, f2, f3)` naming an EXTRA row's four field kinds; the file is included multiple times to generate both the enum and dispatch tables. Handler dispatch is in `handlers.incl` (auto-generated by `tox -e handlers` from `tools/opimpl.py`). Per-opcode implementations live in `koskari/lib/opcode/`.
- **Evaluator** (`eval.c`): Custom stackless bytecode evaluator. Supports coroutines, delimited multi-shot continuations (prompt/shift and call/cc), dynamic wind/unwind, and ambiently async execution (awaitable results are automatically awaited in-place). Entry point: `koskari_eval(ctx, s, send_val, throw_typ, throw_exc)`, where `s` is the calling thread's record or NULL.
- **DynChain** (`dynchain.c/h`, `dynchain/`): Event-driven dynamic extent node chain tracking `with`, `try`, dynamic wind, parameterize, and continuation boundaries.
- **Transforms** (`transform.c/h`, `transform/`): the shared body of the lazy `KosIter` providers — `map`, `filter`, `zip` (builtins) and the `koskari.itertools` set. Each provider under `transform/` supplies only its `ki_step`, the resume chain that step arms, and its type object; `transform.h` declares them all and `koskari_transform_init` readies and registers them from one table.

Every subdirectory under `koskari/lib/` (`dynchain/`, `eval/`, `func/`, `matcher/`, `opcode/`, `transform/`) holds fragments textually `#include`d into a top-level unit. They are `depends` in `setup.py`, never `sources`, and the `.c` glob in `tests/native/tests.mk` stays top-level for the same reason.

### Python Compiler Layer

- **Reader** (`koskari/reader/`): Parses s-expressions. `parser.py` contains `Reader`, `SourceStream` (wraps a C `BaseSourceStream`), and `LayoutReader` which converts indentation-based layout blocks into s-expression forms. Layout handlers for `if`, `cond`, `try`, `class`, etc. live in `koskari/reader/layouts/`.
- **Compiler** (`koskari/compile/`): `compiler.py` converts source forms into bytecode `Code` objects. Special form handlers are in `compile/specials/` (one file per form family: `lambda_.py`, `let.py`, `conditionals.py`, `continuations.py`, etc.). Compile-time pragmas are in `compile/pragma/`.
- **Lexer** (`koskari/lexer/`): Token stream used by the REPL and LSP. The prompt_toolkit REPL integration is in `koskari/lexer/prompt_toolkit/`.
- **Serializer** (`koskari/serialize/`): Codex format for persisting compiled `Code` objects (`.kio` files).

### Bootstrap and Module System

- `koskari/bootstrap/*.ki` — Core builtins written in Koskari itself (`basics.ki`, `_functions.ki`, `_conditionals.ki`, etc.). These are compiled and loaded at package import time by `koskari/bootstrap/__init__.py`.
- `koskari/__init__.py` installs the import hook via `koskari.importer`, which allows `import` of `.ki` source files and `.kio` compiled objects.
- `koskari.pth` — Installed beside the package; its `import koskari` runs `koskari/__init__.py` at interpreter startup, so the import hooks activate automatically in an installed environment.

### Testing

Tests run in 9 ordered phases via `tools/pyphase.py` (invoked by `tox -e test`):

| Phase | Marker | Coverage |
|---|---|---|
| 1 | `phase_lib` | C extension types, opcodes |
| 2 | `phase_infra` | matcher, reader, lexer, dis |
| 3 | `phase_compile` | compiler helpers, syntax, bytecode |
| 4 | `phase_specials` | special form compilation |
| 5 | `phase_importer` | import hooks |
| 6 | `phase_basics` | koskari-written builtins |
| 7 | `phase_cli` | CLI |
| 8 | `phase_reproducers` | full-stack regression scenarios |
| 9 | `phase_extras` | pygments, sphinx, lsp |

Native memory tests (C-level) require a container: `make test-native`, `make test-asan`, `make test-valgrind`.

### Corpus (`docs/corpus/records/`)

Language behavior test cases stored as multi-document YAML shards. Each record has `id`, `feature`, `source`, and `verify` fields (with expected results at `read`, `expand`, `compile`, and/or `eval` phases). Export to Parquet: `make corpus-parquet`.

For questions about Koskari language behavior, syntax, special forms, macros, layouts, or documented/verified examples, query the `koskari-corpus` MCP server (`search_docs`, `search_examples`, `get_reference`) before grepping source — it is the fastest authoritative path.
