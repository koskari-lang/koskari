# tree-sitter-koskari

An editor-neutral [Tree-sitter](https://tree-sitter.github.io/) grammar for the
Koskari Lisp dialect (`.ki`). It parses s-expressions, atoms (symbols, numbers,
strings, keywords), quote/quasiquote/unquote, collection literals (`#(`, `#[`,
`#{`), and indentation-based **layout blocks** (`name args:` headers with an
indented body) via an external scanner that emits indent/dedent tokens.

The same grammar and highlight queries drive every Tree-sitter editor below
(Helix, Zed, Neovim). Editor-specific glue lives next door under
`editors/helix/` and `editors/zed/`.

## Layout

```
grammar.js                 grammar definition (edit this)
src/scanner.c              hand-written external scanner (indent/dedent) — load-bearing
src/parser.c               GENERATED by tree-sitter, committed on purpose (see below)
src/tree_sitter/           GENERATED headers, committed
queries/
  highlights.scm           GENERATED from highlights.scm.j2 (do not hand-edit)
  highlights.scm.j2        template; special/layout names come from tools/editor_tokens/spec.yml
  indents.scm              layout-block indentation
```

## Generated, but committed

Two classes of files here are generated yet checked in, matching how the other
editor assets (TextMate JSON, Emacs `.el`) are handled:

- **`queries/highlights.scm`** is rendered from `highlights.scm.j2` against
  `tools/editor_tokens/spec.yml`, because the set of special forms and layout
  heads it highlights changes as the language evolves. Regenerate with
  `make regen-editors` (never edit the `.scm` by hand).
- **`src/parser.c`** and **`src/tree_sitter/`** are produced by
  `tree-sitter generate`. They are committed so consumers do not need the
  Tree-sitter CLI — in particular **Zed**, which builds the grammar from a
  cloned git revision rather than your working tree. Regenerate with
  `make editors-grammar` (needs Node + npm) after editing `grammar.js`.

## Capture names

The queries use Helix-dialect, hierarchical capture names (`@keyword.control`,
`@constant.numeric`, `@variable.other`, …). These theme natively in Helix and
degrade gracefully in Zed and Neovim, which both do longest-prefix fallback
(`constant.numeric` → `constant`, `keyword.control` → `keyword`). A single
query set therefore serves all three editors.

## Status

Highlighting and layout parsing are solid on canonical Koskari (the entire
`koskari/` source tree parses without error). Known v1 limitations:

- A defined name in a layout header (`define foo …:`) is highlighted as a
  keyword like the head, not as a distinct definition name.
- `,` is always parsed as unquote; this is correct inside quasiquote (the only
  place Koskari uses it) and produces an error on the non-Koskari "trailing
  comma" idiom, which is intended.
- Dotted attribute access (`foo.bar`) is one symbol token rather than a
  structured attribute node.

# Installing per editor

First, from a checkout of this repository, build the grammar if you have edited
`grammar.js` (otherwise the committed `src/parser.c` is ready to use):

```sh
make editors-grammar    # npm install + tree-sitter generate
```

## Helix

1. Install the LSP so diagnostics/hover/completion work:
   `pip install -e ".[lsp]"` (provides `koskari-lsp`).
2. Merge `editors/helix/languages.toml` into `~/.config/helix/languages.toml`
   and set the grammar source to an **absolute** path to this directory:
   ```toml
   [[grammar]]
   name = "koskari"
   source = { path = "/abs/path/to/koskari/editors/tree-sitter" }
   ```
3. Fetch and build the grammar:
   ```sh
   hx --grammar fetch
   hx --grammar build
   ```
4. Make the queries discoverable:
   ```sh
   ln -s /abs/path/to/koskari/editors/tree-sitter/queries \
         ~/.config/helix/runtime/queries/koskari
   ```
5. Verify: `hx --health koskari` should show Highlight enabled; open a `.ki`
   file.

## Zed

Zed is Tree-sitter–based but builds the grammar to WASM from a cloned **git
revision**, so it reads the committed `src/parser.c` (no Tree-sitter CLI
needed). It does require the Rust toolchain via `rustup`.

1. Edit `editors/zed/extension.toml` so the grammar points at your local
   checkout and a commit that contains `editors/tree-sitter`:
   ```toml
   [grammars.koskari]
   repository = "file:///abs/path/to/koskari"
   rev = "<commit sha>"
   path = "editors/tree-sitter"
   ```
2. Commit your changes so that `rev` exists (Zed clones the committed state, not
   the working tree).
3. In Zed, open the command palette and run **`zed: install dev extension`**,
   then select the `editors/zed/` directory.
4. Open a `.ki` file. Re-run the install-dev-extension action after changing the
   grammar or bumping `rev`.

## Neovim (nvim-treesitter)

1. Register the parser, pointing at this directory:
   ```lua
   local parsers = require("nvim-treesitter.parsers").get_parser_configs()
   parsers.koskari = {
     install_info = {
       url = "/abs/path/to/koskari/editors/tree-sitter",
       files = { "src/parser.c", "src/scanner.c" },
     },
     filetype = "koskari",
   }
   vim.filetype.add({ extension = { ki = "koskari" } })
   ```
2. `:TSInstall koskari`
3. Copy or symlink `queries/highlights.scm` and `queries/indents.scm` into
   `~/.config/nvim/queries/koskari/`.
