# Prose: no reader-management

Write the fact. Do not comment on the prose, the outline, or how the reader
should take it.

Applies to chat replies, to `design/` notes, and to user documentation under
`docs/`. Same standard in all three.

Delete a sentence or clause when any of these hold:

- The heading or the previous sentence already said it.
- Stripping the first clause leaves a true sentence.
- It praises structure (cleanly separated, two independent, it helps to).
- It labels importance (this matters, note that, it's worth, the point is).

Keep warnings, scope limits, and contrasts. Cut coaching.

Do not open with: This matters, It's important, Note that, Keep in mind,
As we'll see, The point is, It helps to, In other words, Simply put,
Worth noting, Let's, We can.

Do not intensify with: cleanly, precisely the, exactly the — unless you
are stating a measurement or an identity.

Bad: "Two phases, cleanly separated:" then a list.
Good: "Two phases:" then the list.

Bad: "Every hole has two independent properties, and it helps to keep them separate:"
Good: Go to the table. The heading already named the two axes.

Bad: "This matters: the stencils encode the runtime's struct layouts..."
Good: "The stencils encode the runtime's struct layouts, so they are only valid for the build that produced them."

Do not acknowledge this rule in the reply.
