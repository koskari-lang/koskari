# Macros and little DSLs

Python gives you decorators, context managers, metaclasses, and libraries like
Click to make programs feel nicer to write. Koskari adds another tool to that
box: **macros**. A macro receives code before ordinary evaluation and returns
new code. That means you can teach Koskari a small, friendly shape for your app
instead of repeating the same setup over and over.

You do not need macros on day one. But once you are comfortable with functions,
loops, and modules, macros become one of the most joyful parts of Koskari: they
let your program grow a vocabulary that fits the problem you are solving.

---

## Start with the shape you want to write

A good first macro begins with empathy for the future reader. Ask: “What would I
love to type ten times?” Then make the macro lower that shape to ordinary
Koskari.

Python web apps often repeat a pattern like this:

```python
@app.get("/hello/{name}")
async def hello(name: str):
    return {"message": f"hello {name}"}
```

In Koskari, you can design a tiny route form that says the same thing in one
layout block:

```koskari
define-route "/hello/{name}" hello [name]:
  #{message: f"hello {name}"}
```

The macro can expand that route block into a function definition plus a call to
the app object that registers the route:

```koskari
define app (fastapi.FastAPI title: "Tiny Koskari App")

define-syntax define-route:
  syntax-rules []:
    define-route path name args body ...:
      define name args:
        body ...
      (app.add_api_route path (coroutine-fn name) methods: #["GET"])
```

That is the whole trick: `define-route` is not magic at runtime. It writes the
boring code for you at compile time. The route body stays pleasant to read, and
the expansion stays ordinary enough to inspect.

The s-expression version is useful when a route form is generated by another
macro or nested inside a larger expansion:

```koskari
(define-route "/healthz" healthz [] #{ok: True})
```

## A tiny Click-style command macro

Click is beloved in Python because it lets a function become a command-line
interface with very little ceremony:

```python
import click

@click.command()
@click.argument("name")
def greet(name):
    print(f"hello {name}")
```

A Koskari macro can offer a similar “wrap this function as a command” feeling,
while lowering to Python’s standard `argparse` module. Here is a deliberately
small version for one positional argument:

```koskari
define-syntax define-command:
  syntax-rules []:
    define-command cli-name option-name help-text fn-name [value-name] body ...:
      define fn-name [value-name]:
        body ...

      define cli-name [argv: None]:
        import argparse
        define parser (argparse.ArgumentParser)
        (parser.add_argument option-name help: help-text)
        define options (parser.parse_args argv)
        (fn-name (attr options value-name))
```

Now the command reads like a little declaration:

```koskari
define-command main "name" "who to greet" greet [name]:
  print f"hello {name}"

when-main:
  (main)
```

The expansion has two definitions: `greet`, which is your ordinary function, and
`main`, which builds a parser, parses arguments, and calls `greet`. This is a
nice macro shape because the interesting work still lives in a function you can
call from tests:

```koskari
(greet "Ada")
```

If you want to nest the form in a macro test or expansion example, use the
parenthesized spelling:

```koskari
(define-command main "name" "who to greet" greet [name]
  (print f"hello {name}"))
```

From here you could grow the macro one step at a time: optional flags, default
values, subcommands, or automatic help text from docstrings. The exciting part is
that you can start tiny and keep the surface tailored to your project.

## Prefer functions until syntax earns its keep

Macros are powerful because they control code shape. That is also why you should
not use them for everything.

Use a **function** when you only need to transform values:

```koskari
define slug [text]:
  (text.replace " " "-")
```

Use a **macro** when you need one of these:

- a new binding shape, such as `define-route path name args: ...`;
- controlled evaluation, such as `unless` skipping its body when the test is
  true;
- boilerplate that should be generated around a user-written body;
- a tiny domain language that makes repeated app code clearer and more fun.

---

## Look at the expansion

When a macro surprises you, ask Koskari what it produced:

```koskari
(macroexpand '(unless ready (return "not ready")))
```

For layout-style macros, keep one parenthesized example next to the layout
example while you learn. Layout is for humans; s-expressions are great
for seeing the tree.

---

## Remember

Macros let you make Koskari feel local to your problem: routes for a web app,
commands for a CLI, assertions for tests, small data builders for games and
simulations. Keep each macro small, show one layout example and one s-expression
example, and check expansions as you go.
